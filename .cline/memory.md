## Durable Decisions
- **Stack:** Next.js 16 App Router + TS + Tailwind v4 + Prisma 6 + Zustand + Lucide React + Zod.
- **Tailwind v4:** tokens in `src/app/globals.css` `@theme` (`background` #0B0E14, `surface` #151B26, `border-subtle` #232B3B, `accent` #E50914, `gold` #FBBF24, `text-primary` #F9FAFB, `text-secondary` #9CA3AF; fonts `display`/`body` via `--font-jakarta`/`--font-inter`). Tailwind v4 has no `tailwind.config.ts` — CSS-first config is the equivalent.
- **Next 16 API notes:** `next/image` uses `preload` (`priority` deprecated); layouts use typed `LayoutProps<"/">`.
- **Data layer:** `src/lib/tmdb.ts` server-only client — reads `TMDB_API_KEY` (preferred) or `NEXT_PUBLIC_TMDB_API_KEY` (fallback); auto-detects v3 key (32-hex → `api_key` query param) vs v4 token (→ Bearer header). Mock fallback (`src/lib/mock-data.ts`) remains for absent key / failed fetches. Full helper surface: `getCatalogSections`, `getFeaturedTitle`, `getTitleDetails`, `getTitleById`, `getGenres`, `searchTitles` (delegates), `searchFullCatalog(query, page)`, `getDiscoverMedia(type, page, sortBy, genreId, year)` → `DiscoverResult {titles, page, totalPages}` (movie→`primary_release_year`, tv→`first_air_date_year`; tv date-sort translation; vote_count floor), `getTrending(type, window)`. All null-safe (never throw) — the user's pasted draft helper was merged into this pattern rather than replacing it.
- **TMDB credential:** user-supplied v3 API key lives in `.env` as both `TMDB_API_KEY` and `NEXT_PUBLIC_TMDB_API_KEY` (user's requested name); `.env.example` documents both. Server-only usage preferred.
- **Watchlist state:** Zustand + localStorage persist (`src/store/watchlist.ts`); hydration-safe via `useSyncExternalStore` (React hooks lint forbids setState-in-effect).
- **Watch route (user-supplied design, SITE_SPEC IA):** `/watch/[id]?type=movie|tv&season=&episode=` — server page (Next 16 `PageProps` helper, Zod-validated, `notFound` on invalid). When `type` omitted, mediaType resolved server-side via `getTitleById()` (probes movie, then TV). Renders `StreamPlayer` client component: full-screen iframe mapped by TMDB ID. MediaCard + HeroBanner CTAs link to `/watch/{id}?type={mediaType}`.
- **TV episode drawer (spec `<meaningful_interactions>`):** for TV, watch page fetches `getTvSeasons(id)` server-side and passes `seasons` to `StreamPlayer`, which shows an `EpisodeDrawer` (sliding right-side sheet, `translate-x` transition, backdrop). Selecting a season lazy-loads its episodes via `/api/tv/season?id=&season=` (Zod-validated proxy → `getTvSeasonEpisodes`); clicking an episode `router.push`es `/watch/{id}?type=tv&season=&episode=` so the embed + URL update. Header button shows current `S{season} · E{episode}`.
- **Iframe attributes (revised):** the `sandbox` attribute was **removed** — embed hosts reject it with "This content can't be embedded in a sandboxed frame". `StreamPlayer` iframe now uses only `referrerPolicy="origin"` + `allow="autoplay; fullscreen; picture-in-picture; encrypted-media"` + `allowFullScreen`. (Early hardening attempt didn't work with these providers; do not re-add sandbox.)
- **Continue Watching (local):** `src/store/history.ts` (Zustand + localStorage, `cinestream-history`, max 20, newest-first) — `StreamPlayer` records `{id, mediaType, title, posterUrl, season, episode}` on view via effect. `ContinueWatchingRow` (home page, above TMDB rows) reads it, hydration-safe via `useSyncExternalStore`, hidden until populated; TV entries deep-link to the saved episode. `MediaCard` gained an optional `href` override for this.
- **Catalog sections (Phase 2):** `getCatalogSections()` fetches Trending Movies (`/trending/movie/week`), Popular Series (`/tv/popular`), Top Rated (`/movie/top_rated`), New & Upcoming (`/movie/upcoming`) — 14 titles each, 1h ISR.
- **Browse route (v2, discover-based):** `/browse` — server shell fetches `getGenres()` only; `BrowseCatalog` client component loads the catalog via `/api/discover` (Zod-validated server proxy → `getDiscoverMedia`). Movies/Series toggle, sort (Most Popular / Highest Rated w/ auto `vote_count.gte=300` / Recently Released w/ tv→`first_air_date.desc` translation), genre filter, **true infinite scroll** (IntersectionObserver with 600px rootMargin + auto-load) AND an accessible "Load More Titles" button fallback (TMDB 500-page cap). Skeleton grid while loading; `MediaCard fluid` in grid with explicit `loading="lazy"`. Superseded + removed: `BrowseGrid` component and `getBrowseCatalog()` helper.
- **Discover API:** `/api/discover?type=&sort=&genre=&year=&page=` — Zod-validated, returns `{ titles, page, totalPages }`.
- **Search route:** `/search?q=` — server shell passes initialQuery to `SearchClient` (client, 350ms debounce, AbortController) hitting `/api/search` route handler (Zod 1–100 chars, server-side `searchTitles()` via `/search/multi`, person results filtered). Header search bar already pushed `/search?q=`.
- **Multi-server player:** `StreamPlayer` has a 4-server switcher toolbar (Server 1 vidsrc.to, Server 2 vidsrc.xyz, Server 3 2embed.cc, Server 4 autoembed.co) with per-provider movie/TV URL builders (patterns are generated defaults from provider docs — verify if a source breaks). iframe re-mounts on switch via key. Fixes "media unavailable" by letting users hop servers.
- **React hooks lint:** no synchronous setState in effect bodies — debounce callbacks must contain all state updates (SearchClient pattern).
- **BrowseCatalog concurrency guard:** `inFlightRef` (one request at a time) + `requestIdRef` (drop superseded responses) prevent the IntersectionObserver from firing multiple appends before `loading` flips — this was the cause of "two children with the same key" duplicate-key errors. Appends also dedupe by `mediaType-id` as a safety net (TMDB discover pages can overlap).
- **Dev-server quirk:** renaming a dynamic route segment (e.g. `[mediaType]/[id]` → `[id]`) while `next dev` runs leaves a stale router cache that 404s all `/watch/*` until the dev server is restarted — production build is unaffected.
- **Hero copy (Phase 1 sign-off):** spec tagline eyebrow + "Watch Trailer"/"Start Watching" CTAs + mute toggle + quality badges, per SITE_SPEC `<copywriting>`.
- **Editor quirk:** `write_to_file`/`replace_in_file` fail when target file is open in a VS Code tab ("User closed text editor"); fallback is shell heredoc (`cat > file << 'EOF'`). Ghost tabs (`src/components/ui`, `.cline/memory.md</path`) can confuse the IDE — reload window to clear.
- **Phantom-diagnostics fix:** when files are deleted/renamed (e.g. removed `watch/[mediaType]/[id]/page.tsx` + `BrowseGrid.tsx`), VS Code's Problems panel keeps reporting their old errors. Root cause is `tsconfig.json` → `"incremental": true` + a stale root `tsconfig.tsbuildinfo` cache. Fix: `rm -f tsconfig.tsbuildinfo` (regenerates on next tsc/build) then reload the VS Code window (Developer: Reload Window). Always cross-check with `npx tsc --noEmit` — if it's 0 errors and `next build` passes, the code is healthy and the panel is stale.
- `.vscode/settings.json`: `css.lint.unknownAtRules: ignore` for Tailwind v4 at-rules.
- **Skills library:** `.cline/skills/` holds per-library guides, each led by user-supplied **Core Principles**: `shadcn-ui.md` (CLI-first; dialog=trailer/synopsis modals, sheet/drawer=episodes, dropdown-menu=server+subtitle switching, skeleton=poster loading; never ad-hoc modals), `embla-carousel.md` (dragFree, hover-only arrows, flex-basis slide widths 2-up mobile / 5-up desktop), `lucide-icons.md` (Design Mapping incl. RotateCcw/Cw for 10s skip; aria-label mandatory on icon buttons), `vidstack-player.md` (failover protocol: multi-server iframe primary → HLS w/ custom scrub/volume/speed when .m3u8 available; 2.5s inactivity chrome hide). Each also carries repo-specific setup/tokens/gotchas. Consult before touching those areas.

Arrow state sync defers initial read via setTimeout (set-state-in-effect lint).
